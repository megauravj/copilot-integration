# Liferay 7.4 Blog CMS Service Builder Module

## Overview

This Liferay 7.4 Service Builder module implements a complete blog content management system with two main entities: **BlogPost** and **BlogComment**. The module supports multi-tenancy, provides comprehensive finder methods, and generates full CRUD operations through Service Builder.

## Architecture

```
Portlet/REST API Layer
         ↓
Local Service Interfaces (BlogPostLocalService, BlogCommentLocalService)
         ↓
Service Implementation (LocalServiceImpl)
         ↓
Persistence Layer (DAO - Data Access Objects)
         ↓
Database (BlogCMS_BlogPost, BlogCMS_BlogComment)
```

## Entities

### 1. BlogPost Entity

Represents a blog post in the content management system.

**Fields:**
| Field | Type | Required | Description |
|-------|------|----------|-------------|
| postId | long | Yes | Primary key, auto-generated |
| groupId | long | Yes | Site/Community ID (multi-tenancy) |
| companyId | long | Yes | Company/Instance ID |
| userId | long | Yes | User ID of the post author |
| userName | String | No | Username of the post author |
| createDate | Date | Yes | Post creation timestamp |
| modifiedDate | Date | Yes | Last modification timestamp |
| title | String | Yes | Post title (max 255 chars) |
| content | String | No | Post content (text blob) |
| status | String | No | Post status (DRAFT, PUBLISHED, ARCHIVED) |
| viewCount | long | No | Number of views (default: 0) |

**Finder Methods:**
- `findByGroupId(long groupId)` - Get all posts in a site
- `findByUserId(long userId)` - Get all posts by an author
- `findByStatus(String status)` - Get posts by status
- `findByGroupIdAndStatus(long groupId, String status)` - Get posts by site and status
- `findByGroupIdAndUserId(long groupId, long userId)` - Get posts by author in a site

**Relationships:**
- References `User` entity (author)
- References `Group` entity (site)

### 2. BlogComment Entity

Represents a comment on a blog post.

**Fields:**
| Field | Type | Required | Description |
|-------|------|----------|-------------|
| commentId | long | Yes | Primary key, auto-generated |
| postId | long | Yes | Foreign key to BlogPost |
| groupId | long | Yes | Site/Community ID |
| companyId | long | Yes | Company/Instance ID |
| userId | long | Yes | User ID of the commenter |
| userName | String | No | Username of the commenter |
| createDate | Date | Yes | Comment creation timestamp |
| modifiedDate | Date | Yes | Last modification timestamp |
| commentText | String | No | Comment content |

**Finder Methods:**
- `findByPostId(long postId)` - Get all comments for a post
- `findByUserId(long userId)` - Get all comments by a user
- `findByGroupId(long groupId)` - Get all comments in a site
- `findByPostIdAndUserId(long postId, long userId)` - Get user's comments on a post

**Relationships:**
- References `BlogPost` entity (parent post)
- References `User` entity (commenter)
- References `Group` entity (site)

## Building the Module

### Prerequisites

- Liferay 7.4 server installed
- Blade CLI installed (optional but recommended)
- Gradle 6.x or higher
- Java 8 or higher

### Step 1: Generate Service Layer

The `buildService` Gradle task generates all the necessary service classes from `service.xml`:

```bash
./gradlew buildService
```

This command generates:
1. **Model Classes**: `BlogPost.java`, `BlogPostImpl.java`, `BlogComment.java`, `BlogCommentImpl.java`
2. **Service Interfaces**: `BlogPostLocalService.java`, `BlogCommentLocalService.java`
3. **Service Implementations**: `BlogPostLocalServiceImpl.java`, `BlogCommentLocalServiceImpl.java`
4. **Persistence Layer**: Finder and update/insert/delete methods
5. **Database Schema**: `tables.sql`
6. **Exception Classes**: `NoSuchBlogPostException`, `NoSuchBlogCommentException`

### Step 2: Build the Module

```bash
./gradlew clean build
```

### Step 3: Deploy to Liferay

Using Blade CLI:
```bash
blade deploy build/libs/blog-post-lfr.jar
```

Or copy the JAR to the deployment directory:
```bash
cp build/libs/blog-post-lfr.jar /path/to/liferay-home/osgi/modules/
```

## Usage Examples

### Example 1: Create a Blog Post

```java
// Inject the service
@Reference
private BlogPostLocalService blogPostLocalService;

// Create a new post
long groupId = 10189; // Site ID
long userId = 10123;  // Author ID

BlogPost newPost = blogPostLocalService.addBlogPost(
    groupId,
    userId,
    "Hello World",           // title
    "This is my first blog", // content
    "PUBLISHED",             // status
    new ServiceContext()
);
```

### Example 2: Get Published Posts in a Site

```java
List<BlogPost> publishedPosts = blogPostLocalService.getBlogPostsByGroupIdAndStatus(
    groupId,
    "PUBLISHED"
);

for (BlogPost post : publishedPosts) {
    System.out.println(post.getTitle() + " - Views: " + post.getViewCount());
}
```

### Example 3: Add a Comment to a Post

```java
@Reference
private BlogCommentLocalService blogCommentLocalService;

long postId = 100001;
long commenterId = 10456;

BlogComment comment = blogCommentLocalService.addBlogComment(
    postId,
    groupId,
    commenterId,
    "Great post!",
    new ServiceContext()
);
```

### Example 4: Get Comments for a Post

```java
List<BlogComment> comments = blogCommentLocalService.getBlogCommentsByPostId(postId);

System.out.println("Total comments: " + comments.size());
for (BlogComment comment : comments) {
    System.out.println(comment.getUserName() + ": " + comment.getCommentText());
}
```

### Example 5: Update Post Status

```java
BlogPost post = blogPostLocalService.getBlogPost(postId);
post.setStatus("ARCHIVED");
post.setModifiedDate(new Date());
blogPostLocalService.updateBlogPost(post);
```

### Example 6: Multi-tenancy - Get Posts Scoped to User's Site

```java
// Always filter by groupId to ensure proper multi-tenancy
long userSiteId = themeDisplay.getScopeGroupId();
List<BlogPost> sitePosts = blogPostLocalService.getBlogPostsByGroupId(userSiteId);
```

## Database Schema

After `buildService` runs, the following tables are created:

### BlogCMS_BlogPost Table

```sql
CREATE TABLE BlogCMS_BlogPost (
    postId BIGINT NOT NULL PRIMARY KEY,
    groupId BIGINT,
    companyId BIGINT,
    userId BIGINT,
    userName VARCHAR(255),
    createDate DATETIME,
    modifiedDate DATETIME,
    title VARCHAR(255) NOT NULL,
    content LONGTEXT,
    status VARCHAR(50),
    viewCount BIGINT,
    uuid_ VARCHAR(75),
    UNIQUE KEY (groupId, uuid_),
    KEY idx_groupId (groupId),
    KEY idx_userId (userId),
    KEY idx_status (status),
    KEY idx_groupId_status (groupId, status)
);
```

### BlogCMS_BlogComment Table

```sql
CREATE TABLE BlogCMS_BlogComment (
    commentId BIGINT NOT NULL PRIMARY KEY,
    postId BIGINT,
    groupId BIGINT,
    companyId BIGINT,
    userId BIGINT,
    userName VARCHAR(255),
    createDate DATETIME,
    modifiedDate DATETIME,
    commentText LONGTEXT,
    uuid_ VARCHAR(75),
    UNIQUE KEY (groupId, uuid_),
    KEY idx_postId (postId),
    KEY idx_userId (userId),
    KEY idx_groupId (groupId),
    KEY idx_postId_userId (postId, userId),
    FOREIGN KEY (postId) REFERENCES BlogCMS_BlogPost(postId)
);
```

## Liferay 7.4 Configuration

### service.xml Settings

```xml
<service-builder package-path="com.liferay.blog.cms" auto-namespace-tables="false">
  <namespace>BlogCMS</namespace>
```

**Explanation:**
- **package-path**: Generated classes will be in `com.liferay.blog.cms` package
- **auto-namespace-tables**: false - We manually specify the namespace
- **namespace**: BlogCMS - Database table prefix

### Entity Configuration

```xml
<entity name="BlogPost" local-service="true" remote-service="true" uuid="true">
```

**Explanation:**
- **local-service**: true - Generates local services (same JVM)
- **remote-service**: true - Generates SOAP web services
- **uuid**: true - Adds UUID field for content distribution

## Multi-Tenancy

This module is fully multi-tenant aware:

1. **groupId**: Scopes all data to a specific site/community
2. **companyId**: Scopes all data to a specific Liferay instance
3. **Finder Methods**: Always filter by groupId when retrieving data

**Best Practice:**
```java
// CORRECT: Scoped to a specific site
List<BlogPost> posts = blogPostLocalService.getBlogPostsByGroupId(groupId);

// NEVER DO THIS: Would get posts from all sites
// This method doesn't exist by design
// List<BlogPost> allPosts = blogPostLocalService.getAllBlogPosts();
```

## Performance Optimization

### Use Finder Methods
Service Builder automatically creates indexes for all finder columns.

```java
// Efficient: Uses index on groupId
List<BlogPost> posts = blogPostLocalService.getBlogPostsByGroupId(groupId);

// Even more efficient: Uses composite index on (groupId, status)
List<BlogPost> published = blogPostLocalService.getBlogPostsByGroupIdAndStatus(
    groupId, 
    "PUBLISHED"
);
```

### Pagination

```java
// Get page 1 with 20 items
List<BlogPost> posts = blogPostLocalService.getBlogPostsByGroupId(groupId);
int pageSize = 20;
List<BlogPost> page1 = posts.subList(0, Math.min(pageSize, posts.size()));
```

### Avoid N+1 Queries

```java
// INEFFICIENT: Loads user for each post
for (BlogPost post : posts) {
    User author = userLocalService.getUser(post.getUserId()); // N+1 problem
}

// EFFICIENT: Batch load users
Set<Long> userIds = posts.stream()
    .map(BlogPost::getUserId)
    .collect(Collectors.toSet());
List<User> users = userLocalService.getUsers(userIds);
```

## Error Handling

## Extending the Module

### Adding Custom Service Methods

1. Edit `*LocalServiceImpl.java` after `buildService` runs:

```java
// BlogPostLocalServiceImpl.java
public List<BlogPost> searchByKeyword(long groupId, String keyword) {
    // Custom implementation
    return blogPostPersistence.findByGroupId(groupId);
}
```

2. Rebuild and redeploy:

```bash
./gradlew clean build
blade deploy build/libs/blog-post-lfr.jar
```

### Adding New Finder Methods

1. Add to `service.xml`:

```xml
<finder name="GroupIdAndStatusAndCreatedDateGreaterThan" return-type="Collection">
    <finder-column name="groupId" />
    <finder-column name="status" />
    <finder-column name="createDate" op="greater-than" />
</finder>
```

2. Run `buildService` again and implement custom logic

## Troubleshooting

### Issue: Service methods not found after deployment

**Solution:**
1. Ensure `buildService` was executed: `./gradlew buildService`
2. Rebuild the module: `./gradlew clean build`
3. Redeploy the JAR

### Issue: Database tables not created

**Solution:**
1. Check Liferay logs for SQL errors
2. Verify database permissions
3. Ensure `buildService` was executed before deployment

### Issue: Multi-tenancy data leakage

**Solution:**
Always filter by `groupId` in your queries to ensure proper data isolation.
